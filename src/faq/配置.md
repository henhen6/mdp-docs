### 1. 修改了 Nacos 上的配置不生效

确认配置对应的属性 Bean 是否标注了 `@RefreshScope`：`SystemProperties`、`MsgProperties` 支持动态刷新；`DatabaseProperties` 等启动期固定的属性类不支持，修改后必须重启服务。

详见：[后端配置-微服务版](../config/后端配置-微服务版.md)

### 2. 改了 `application.yml` 不生效

按 Spring 配置覆盖顺序排查：是否被 `application-{env}.yml`、环境变量或命令行参数覆盖。启动日志中的 `The following profiles are active` 可确认当前激活的环境。

详见：[后端配置-单体版](../config/后端配置-单体版.md)

### 3. 打包后 yml 里的 `@config.nacos.ip@` 没被替换

两个可能：模块 pom 未开启 `<filtering>true</filtering>`；或打包命令漏了 `-P` 参数导致 `profile.active` 未定义——此时 filter 路径拼不出来，**Maven 会静默跳过替换而不报错**。可解压 jar 检查 `BOOT-INF/classes/application.yml` 验证替换结果。

详见：[编译期配置filters](../config/编译期配置filters.md)

### 4. 不想重新打包，临时更换 Nacos 地址

配置采用 `${NACOS_IP:@config.nacos.ip@}` 写法时可用环境变量覆盖，启动前设置即可：

```bash
NACOS_IP=新地址 NACOS_PORT=8848 java -jar boot-server.jar
```

支持覆盖 `NACOS_IP`、`NACOS_PORT`、`NACOS_NAMESPACE`、`NACOS_USERNAME`、`NACOS_PASSWORD`、`SENTINEL_DASHBOARD`。

详见：[编译期配置filters](../config/编译期配置filters.md)

### 5. 误删了内置系统参数怎么办

参照系统配置文档的参数清单重新插入同名 `uniq_key` 记录，或从 `mdp/docs/mdp.sql` 中找到对应 `INSERT` 语句恢复。删除标注「请勿删除」的参数会导致登录验证码、密码策略等功能异常。

详见：[系统配置](../config/系统配置.md)

### 6. 系统参数（mdc_config）改了没生效

依次确认：参数 `state` 为启用状态；改的是正确组织下的配置（**组织级配置会遮蔽全局值**）；极少数 Redis 缓存异常时重新保存一次（触发缓存删除）即可。正常情况下参数保存后立即生效，无需重启。

详见：[系统配置](../config/系统配置.md)

### 7. mdc_config 与 Nacos 配置有什么区别

- **Nacos/配置文件**管技术侧：连接地址、中间件、框架参数，部署时确定，修改后可能需重启；
- **mdc_config**管业务侧：策略、阈值、开关，管理员页面上调整，改完即时生效。

判断标准：管理员日常在页面上调的放 `mdc_config`，部署时定死的放配置文件。

详见：[系统配置](../config/系统配置.md)

### 8. 调大上传限制后仍然上传失败

上传限制是三层嵌套关系，**每一层都要 ≥ 业务需要值**：`mdp.upload` → `spring.servlet.multipart` → `dubbo.protocol.payload`。修改 dubbo payload 后 api-server 侧也要同步调整。

详见：[开放平台网关配置](../config/开放平台网关配置.md)

### 9. 开发环境想临时禁用验证码快速登录

设置 `mdp.system.verify-captcha: false`，或不改文件直接用命令行覆盖：

```bash
java -jar boot-server.jar --mdp.system.verify-captcha=false
```

::: warning 生产环境必须保持开启
禁用验证码仅限开发环境，生产环境属安全隐患。
:::

详见：[后端配置-单体版](../config/后端配置-单体版.md)
