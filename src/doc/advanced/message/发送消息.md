本篇讲清**业务模块如何发送消息**。发送永远以「消息模板」为起点：业务只提供模板标识 `templateKey` + 渲染参数 + 接收人，内容渲染、渠道选择、日志统计全部由平台完成。

## 1. 唯一的发送 API：MsgFacade

所有平台内部模块发送消息统一走 `MsgFacade`（`console-api` 模块，`top.mddata.console.facade.message.MsgFacade`）：

```java
public interface MsgFacade {
    /**
     * 根据消息模板发送消息
     *  MsgSendNoticeDto 站内信参数
     *  MsgSendSmsDto    短信发送参数
     *  MsgSendMailDto   邮件消息参数
     *
     * @param data 消息参数
     * @return 消息任务ID
     */
    Long sendByTemplateKey(MsgSendDto data);
}
```

依赖注入即可使用——直接注入 `MsgFacade`，**不要**注入 `MsgTaskService`（那是 console 模块内部实现，跨模块调用必须走 facade）。返回值是消息任务 ID（`Long`），可用于按 `mdc_msg_task` 追踪发送结果。单体版由 `console-boot-impl` 本地直调，微服务版由 `console-cloud-impl` 经 Feign 转发到 console-server 的 `/inner/message/msgTask/sendByTemplateKey`，**对调用方完全透明，代码不用改**。

## 2. 入参

三个 入参DTO 都继承抽象类 `MsgSendDto`（`console-pojo/.../dto/message/`）：

| 字段                               | 类型                      | 说明                                                                |
| -------------------------------- | ----------------------- | ----------------------------------------------------------------- |
| `templateKey`                    | String                  | **必填**。消息模板标识（`mdc_msg_template.key`，唯一）                          |
| `paramList`                      | `List<Kv>`              | 模板占位符参数，用 `addParam(key, value)` 链式添加                             |
| `channel`                        | `MsgChannelEnum`        | 发送渠道：1-后台发送(WEB) / 2-API发送 / 3-JOB发送。**程序化发送必须传 API 或 JOB**（见 §7） |
| `isTiming` / `scheduledSendTime` | Boolean / LocalDateTime | 定时发送（已支持，见 §7）                                                    |
| `bizId` / `bizType`              | Long / String           | 业务追踪字段，API/JOB 发送时指定，方便按业务回查消息任务                                  |

### 2.1 站内信 MsgSendNoticeDto

```java
MsgSendNoticeDto dto = new MsgSendNoticeDto()
        .setTemplateKey("NOTICE")
        .setAuthor("数据同步服务")              // 发布人展示名
        .setMsgCategory(MsgCategoryEnum.NOTICE) // 消息分类：1-待办 2-公告 3-预警
        .setRecipientScope(MsgRecipientScopeEnum.USER) // 接收范围
        .setRecipientIdList(List.of(userId))    // 按 scope 填用户ID列表
        .setUrl("/workbench/user/notice/view")  // 点击消息的跳转地址（站内信专用）
        .addParam("content", "主数据【客户A】已被修改，请查看");

msgFacade.sendByTemplateKey(dto);
```

- `recipientScope`（接收范围）：**0-所有人 / 1-指定用户 / 2-指定角色 / 3-指定部门**。scope 非所有人时 `recipientIdList` 必填——填用户 ID、角色 ID 还是部门 ID 由 scope 决定，发送时由平台展开（角色/部门经 `UserService.listByRoleIds/listByDeptIds` 解析成用户集合）。
- `url` 是接收人点击消息后的跳转地址，前端会路由过去；不填则只能进消息中心查看。
- `msgCategory` 的取值来自 `MsgCategoryEnum`（1-待办 2-公告 3-预警），前端消息中心、通知铃铛按它渲染分类标签。

### 2.2 短信 MsgSendSmsDto / 邮件 MsgSendMailDto

两者结构对称，接收人直接是手机号/邮箱：

```java
// 短信：模板 content = "你的验证码为${code}"
MsgSendSmsDto sms = MsgSendSmsDto.buildApiSender()   // 静态工厂设置 channel=API
        .setTemplateKey("PHONE_REGISTER")
        .addRecipient("13800000000")
        .addParam("code", "836421");
msgFacade.sendByTemplateKey(sms);

// 邮件：模板 content 为 HTML，占位符含 ${code} ${validityPeriod} ${_mdp.appName}
MsgSendMailDto mail = MsgSendMailDto.buildApiSender()
        .setTemplateKey("EMAIL_EDIT")
        .addRecipient("user@example.com")
        .addParam("code", "836421")
        .addParam("validityPeriod", "5");
msgFacade.sendByTemplateKey(mail);
```

静态工厂三选一：`buildApiSender()`（即时）、`buildApiScheduledSender(time)`（定时）、`buildJobSender()`；也可用 `addRecipient(phone)` 链式逐个添加。

## 3. 模板编码与参数

`sendByTemplateKey` 是**契约式调用**：模板在【控制台】运行时配置，编译期在代码不可见——开发者写代码时并不知道系统提供了哪些模板、每个模板需要哪些参数。传错 `templateKey` 会报「消息模板不存在」；而**少传/错传参数不会报错**，只会渲染出空占位符（`${code}` 变成空串）直接发出去。因此平台约定：

::: info 维护一份「模板参数清单」文档作为发送契约
新增或修改消息模板时，**必须同步登记模板编码与参数说明**（本站文档、团队 wiki 或开放平台接口文档均可，保证调用方能查到），内容包括：模板编码 `templateKey`、消息类型、业务用途、占位符参数清单（参数名、含义、示例）。调用方（二开工程师、第三方开发者）一律以该文档为准选模板、传参数，而不是去翻数据库或控制台。
:::

### 3.1 系统内置模板参数清单

以下为平台开箱内置的模板，可直接引用（二开新增模板请续写此表，见 [消息模板](消息模板.md) §5）：

| `templateKey`              | 类型  | 用途                            | 占位符参数                                                |
| -------------------------- | --- | ----------------------------- | ---------------------------------------------------- |
| `NOTICE`                   | 站内信 | 控制台「发布消息」的通用模板（content 为透传占位） | `${title}` 标题、`${content}` 富文本内容                     |
| `PHONE_REGISTER`           | 短信  | 手机号注册验证码                      | `${code}` 验证码                                        |
| `PHONE_LOGIN`              | 短信  | 手机号登录验证码                      | `${code}`                                            |
| `PHONE_EDIT`               | 短信  | 安全设置-换绑手机验证码                  | `${code}`                                            |
| `EMAIL_REGISTER`           | 邮件  | 邮箱注册验证码                       | `${code}`、`${validityPeriod}` 有效期（分钟）                |
| `EMAIL_LOGIN`              | 邮件  | 邮箱登录验证码                       | `${code}`、`${validityPeriod}`                        |
| `EMAIL_EDIT`               | 邮件  | 安全设置-换绑邮箱验证码                  | `${code}`、`${validityPeriod}`                        |
| `FORGET_PASSWORD_BY_EMAIL` | 邮件  | 忘记密码（重置链接邮件）                  | `${resetPasswordUrl}` 重置链接、`${expireTime}` 链接有效期（小时） |

### 3.2 内置参数 `_mdp.*`

除业务参数外，**所有模板可直接使用 `_mdp` 命名空间下的系统内置参数**——发送时无需 `addParam`，渲染引擎自动注入（[消息模板](消息模板.md) §2 说明了注入机制）：

| 参数                       | 含义     | 默认值（yml）             |
| ------------------------ | ------ | -------------------- |
| `${_mdp.appName}`        | 平台名称   | `主数据平台`              |
| `${_mdp.homeWebsiteUrl}` | 平台官网地址 | `https://mddata.top` |

来源是 yml 的 `mdp.msg.param.*`（`MsgProperties`，微服务版经 Nacos 可刷新），**可按需扩展新键**：yml 里加 `mdp.msg.param.supportPhone: '400-xxx'`，所有模板即可直接写 `${_mdp.supportPhone}`。上面的内置模板大量使用 `${_mdp.appName}`、`${_mdp.homeWebsiteUrl}`，换环境部署只需改 yml，不用逐个改模板——这也是把品牌类信息放进 `_mdp` 而不是业务参数的原因。

## 4. 发送时发生了什么

`MsgTaskServiceImpl.sendByTemplateKey()`（console-service）按顺序做四件事：

1. **校验**：模板存在且启用；接收人非空；定时时间需在当前时间 5 分钟之后；**channel 必须是 API 或 JOB**；
2. **建任务**：插入 `mdc_msg_task`（status=待执行，type 取模板的 msgType），把 `paramList` 序列化进 `param` 字段，`bizId/bizType` 原样入库；
3. **接收人入库**：按 DTO 类型批量插入 `mdc_msg_task_recipient`（站内信=用户ID、短信=手机号、邮件=邮箱）；
4. **触发执行**：即时发送 `SpringUtil.publishEvent(new MsgSendEvent(...))`，由监听器异步执行（渲染内容 → 策略发送 → 回写状态/日志/统计）；定时发送则提交 PowerJob 延迟实例，到点执行同一条链路（见 §7）。

方法返回消息任务 ID（`Long`），可用于后续按 `mdc_msg_task` 追踪发送结果。

## 5. 事务边界与异步语义（重要）

监听器 `MsgSendListener` 的注解组合决定了两条硬约束：

```java
@Async
@TransactionalEventListener({MsgSendEvent.class})
public void handleMsgSend(MsgSendEvent event) { ... }
```

- **事务提交后才执行**：`@TransactionalEventListener` 默认在发送方事务 `AFTER_COMMIT` 阶段触发。所以把 `msgFacade.sendByTemplateKey(dto)` 放在 `@Transactional` 方法里是安全的——消息只会在业务数据真正落库后才发出，回滚则不发。
- **异步线程执行**：不阻塞业务主流程；发送失败**不会**影响业务事务，也**没有自动重试**，失败只体现在任务状态（3-执行失败）和接口日志里。需要补偿时请自行扫表重发或自行实现重试（平台的重试能力只在开放平台推送侧，见 [调用链路与扩展点](../open/调用链路与扩展点.md)）。
- 用户上下文通过 `MsgSendEventDto.copy()` 跨线程透传（senderId、orgId 等取自当前登录人）；定时任务/无登录态场景发送前注意上下文是否存在。

## 6. 第三方应用发消息（开放 API）

面向平台外的第三方系统，消息能力以开放接口形式暴露（`md-api` 模块 `MsgOpenService`，Dubbo 实现）：

| 开放接口             | 功能   | 参数要点                                                                 |
| ---------------- | ---- | -------------------------------------------------------------------- |
| `msg.sendNotice` | 发站内信 | `templateKey`、`recipientScope`、`recipientIdList`、`msgCategory`、`url` |
| `msg.sendSms`    | 发短信  | `templateKey`、`recipientList`（手机号）、`paramList`                       |
| `msg.sendEmail`  | 发邮件  | `templateKey`、`recipientList`（邮箱）、`paramList`                        |

实现（`MsgOpenServiceImpl`）只是把开放 DTO 转成 `MsgSendDto` 再调 `MsgFacade`，行为与内部发送完全一致。第三方应用需申请接口权限后经网关调用，接入方式见 [应用接入-接口调用](../../integration/接口调用.md)。

## 7. 实现现状

1. **发送渠道校验只放行 API/JOB**：`sendByTemplateKey` 强制 `channel ∈ {API, JOB}`——「后台发送（WEB）」是控制台「发布消息」页面的专属渠道。您的业务代码请一律用 `buildApiSender()` 或 `buildJobSender()`。
2. **定时发送已实现（PowerJob 延迟实例）**：`isTiming=true` 时任务照常落库（状态=待执行），但不发事件，而是 `MsgTaskServiceImpl.submitTimingJob()` 经 PowerJob OpenAPI `runJob` 向常驻 job 提交一个**延迟实例**（`instanceParams=消息任务ID`，延迟 = 计划时间 − 当前时间）；到点由 worker-server 的 `MsgTaskSendProcessor` 执行，复用 `MsgTaskContext.execSend` 同一条发送链路。使用前需满足：
   - **部署要求**：PowerJob Server 运行中，并在其控制台创建一次常驻 job（`timeExpressionType=API`、处理器填 `top.mddata.worker.processors.MsgTaskSendProcessor` 全限定名），把得到的 jobId 填入 `powerjob.server.msg-job-id`（单体版在 boot-server 的 application.yml，微服务版在 Nacos common.yml）；发送执行发生在 worker-server，需保持其在线；
   - **提交失败随事务回滚**：PowerJob 不可用或未配置时 `submitTimingJob` 直接抛异常，消息任务不会以「待执行」状态滞留；
   - **幂等保护**：`MsgTaskSendProcessor` 执行前用 Redis SETNX 占位（`mdp:msg:send:grab:{taskId}`，1 小时过期），防止 PowerJob 超时重投导致重复发送；发送失败会释放占位，可在 PowerJob 控制台重试实例重新发送。

## 8. 发送前排查清单

发送失败时按顺序检查：

1. 模板是否存在且 `state` 启用？（控制台-消息管理-消息模板）
2. 模板绑定的**接口配置**是否启用？（模板列表可看到关联接口）
3. 接口配置的 `config_json` 参数（SMTP 账号/短信 AccessKey）是否有效？`debug=true` 时会**跳过真实发送**并返回成功；
4. 任务列表/任务详情的「日志」Tab 有该次执行的失败信息（`mdc_interface_log.error_msg`）；
5. 站内信接收人为空：scope=USER 时 ID 是否有效；scope=ROLE/DEPT 时对应角色/部门下是否有启用用户。
