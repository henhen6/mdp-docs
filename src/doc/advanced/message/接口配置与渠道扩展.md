「接口配置」是消息体系的**渠道抽象层**：一条接口配置可以理解为一个可执行的发送渠道实例，对应一个代码中的实现类，无论是短信、邮件、移动端通知、微信模板消息等都对应一个接口配置。它把「用什么方式发（策略）」和「发到哪个账号（密钥参数）」都配置到数据库，让新增渠道、切换短信服务商变成纯配置操作。

渠道是什么意思？就是msg_type字段，也称为接口类型，目前内置站内信、短信、邮件，二开时可以扩展出微信模板消息，钉钉通知等等新渠道。而同一类渠道，不同的厂商调用的sdk，需要的参数都不一样，所以需要对应多个接口配置。

![](/img/doc/开发进阶/接口配置.png)

::: tip 澄清一个容易混淆的点
此处的「接口」与开放平台 API、Webhook 回调**无关**——它是消息渠道的内部抽象。开放平台的事件推送/接口回调见 [调用链路与扩展点](../open/调用链路与扩展点.md)。
:::

## 1. 表结构

```sql
CREATE TABLE `mdc_interface_config` (
  `id`            bigint NOT NULL COMMENT '主键',
  `key`           varchar(255) NOT NULL COMMENT '接口标识',       -- 短信渠道 key 必须与 sms4j 厂商标识一致（见 §3）
  `name`          varchar(255) NOT NULL COMMENT '接口名称',
  `msg_type`      smallint NOT NULL DEFAULT '2' COMMENT '接口类型 [1-站内信 2-短信 3-邮件]',
  `exec_mode`     smallint NOT NULL DEFAULT '1' COMMENT '执行方式 [1-实现类 2-MagicApi 3-脚本]',
  `script`        text COMMENT '实现脚本',                        -- exec_mode=3 时存完整 Groovy 策略类
  `impl_class`    varchar(255) COMMENT '实现类',                  -- exec_mode=1 时填策略 Bean 名
  `magic_api_id`  varchar(255) COMMENT 'MagicApi',               -- exec_mode=2 预留（当前未实现分派）
  `config_json`   longtext COMMENT '参数配置',
  `state`         bit(1) NOT NULL DEFAULT b'1' COMMENT '状态'
);
```

`config_json` 是统一格式的 `[{key,name,remark,value}]` JSON——`name/remark` 供前端渲染编辑表单，`value` 才是实际参数，执行时被解析为 `Map<String,String>` 传给策略：

```json
[
  { "key": "accessKeyId",     "name": "key",       "value": "占位-AccessKeyId" },
  { "key": "accessKeySecret", "name": "秘钥",      "value": "占位-AccessKeySecret" },
  { "key": "signature",       "name": "短信签名",   "value": "主数据平台" },
  { "key": "debug",           "name": "调试模式",   "value": "false" }
]
```

**渠道密钥只存这里**（数据库 longtext，页面维护），不进 yml/Nacos，注意库的访问控制。

MDP内置配置：

| key                                           | 名称    | msg_type | impl_class                    | config_json 要点                                                                                     |
| --------------------------------------------- | ----- | -------- | ----------------------------- | -------------------------------------------------------------------------------------------------- |
| `NOTICE`                                      | 站内信接口 | 1        | `noticeMsgTaskStrategyImpl`   | 无参数                                                                                                |
| `EMAIL`                                       | 邮件接口  | 3        | `mailMsgStrategyImpl`         | smtpServer/port/fromAddress/nickName/username/password/isSsl/isAuth/retryInterval/maxRetries/debug |
| `alibaba` / `tencent` / `baidu` / `chuanglan` | 各短信厂商 | 2        | `aliSmsMsgTaskStrategyImpl` 等 | accessKeyId/accessKeySecret/signature/debug                                                        |

所有渠道都有 `debug` 参数：置 `true` 时策略**跳过真实发送**并直接返回成功——测试环境排查链路时很有用。

## 2. 执行方式

执行器 `MsgTaskContext.execSend()` 按 `exec_mode` 分派：

| 值   | 方式       | 行为                                                                  | 现状                                |
| --- | -------- | ------------------------------------------------------------------- | --------------------------------- |
| 1   | 实现类      | `SpringUtil.getBean(implClass, MsgTaskStrategy.class)` 后调用 `exec()` | **推荐**，可注入其他 Bean                 |
| 3   | 脚本       | `GlueFactory.loadNewInstance(script)` 运行时把 Groovy 源码编译成策略类          | 可用，受沙箱限制（§4）                      |
| 2   | MagicApi | 暂未实现                                                                | **未实现**，仅保存配置时有 `magicApiId` 非空校验 |

每条接口配置创建时会**同步创建同 ID 的接口统计**，删除同理，因此「接口配置 ↔ 接口统计」始终 1:1。控制台接口配置页面的「实现类」下拉来自 `GET /console/message/interfaceConfig/listImplClass`——它列出 Spring 容器里所有 `MsgTaskStrategy` Bean，所以**新策略只要注册为 Bean 就会出现在下拉里**。

## 3. 渠道策略接口

```java
public interface MsgTaskStrategy {
    /** 执行发送；MsgResult 携带渲染后的 title/content、执行结果 */
    MsgResult exec(MsgTaskParam msgTaskParam) throws Exception;
    /** 判定本次执行是否成功（默认 true） */
    default boolean isSuccess(MsgResult result) { return true; }
}
```

`MsgTaskParam` 打包了全部上下文：`msgTask`（含 param 参数）、`recipientList`（任务接收人）、`msgTemplate`（含 sms_template_id）、`interfaceConfig`、`propertyParam`（config_json 解析出的 Map）。

公共基类 `AbstractMsgTaskStrategy` 提供三个工具方法，写新策略时直接复用：

- `parseParam(param)`：任务的 `[{key,value}]` JSON → `LinkedHashMap`；
- `replaceVariable(msgTask, msgTemplate, msgProperties)`：FreeMarker 渲染 title/content（含 `_mdp` 全局参数与 Groovy 脚本加工后返回的参数，见 [消息模板](消息模板.md) §2）；
- `validParam(msgTaskParam)`：非空校验。

已有实现的两个典型写法：

**短信（以阿里云为例）**——简单封装了 sms4j，真正的厂商适配在 sms4j 里：

```java
SmsBlend smsBlend = SmsFactory.getSmsBlend(interfaceConfig.getKey());   // key 必须与 sms4j 厂商标识一致
SmsResponse resp = smsBlend.massTexting(phoneNumberList, msgTemplate.getSmsTemplateId(), params);
```

短信渠道的 `key` 字段有额外约束：`SmsReadByDbConfigImpl`（实现 sms4j 的 `SmsReadConfig` SPI）在应用启动时把 msg_type=2 的接口配置装载进 sms4j，按 `SupplierConstant.ALIBABA/TENCENT/BAIDU/...` 的 switch 映射厂商——所以**短信接口的 key 不能乱取**，必须能对应到 sms4j 支持的厂商标识（sms4j 本身支持 20+ 厂商）。修改 config_json 后需重启服务才会重新装载短信客户端。

**邮件**——基于 org.dromara email-jakarta（mail4j），按「接口ID + 全部参数」拼 key 缓存 `MailClient`，任一参数变更即重建客户端，因此**改 SMTP 配置即时生效、无需重启**。

## 4. Groovy 脚本沙箱（GlueFactory）

脚本模式把整段 Groovy 源码编译为实现 `MsgTaskStrategy` 的类（按源码 SHA-256 缓存）。因为 `SecureASTCustomizer` 对动态 Groovy 的运行时方法分派无效，平台采用**源码级双重扫描**作为安全屏障：

- 剥离空白与字符串字面量后做**危险 Token 黑名单**：进程执行（`Runtime`/`ProcessBuilder`）、文件 IO（`File`/`FileWriter`…）、反射（`Class.forName`/`invoke`/`newInstance`…）、类加载逃逸（`GroovyClassLoader`/`GroovyShell`…）、动态绕过（`metaClass`/`@Grab`…）、网络（`Socket`）、反序列化（`ObjectInputStream`）等；
- 一组**危险调用正则**兜底（`.execute(`、`.forName(`、字符串插值内嵌危险调用等）。

命中即抛 `BizException` 拒绝执行。因此脚本里**不能**读写文件、起进程、开网络、反射；能做的是参数加工、条件判断、字符串处理这类纯逻辑。脚本也不支持 Lombok 注解。

## 5. 新增渠道：两种模式

### 模式 A：实现类（推荐，适合有代码沉淀的正式渠道）

以「微信小程序订阅消息」为例，完整四步：

**① 写策略类**（放在 `console-service` 的 `service/message/strategy/impl/` 下，与既有实现并列）：

```java
@Slf4j
@Service("wechatMiniMsgStrategyImpl")                       // Bean 名即接口配置里的 impl_class
@RequiredArgsConstructor
public class WechatMiniMsgStrategyImpl extends AbstractMsgTaskStrategy {

    @Override
    @Transactional(rollbackFor = Exception.class, propagation = Propagation.REQUIRES_NEW)
    public MsgResult exec(MsgTaskParam msgParam) throws Exception {
        validParam(msgParam);

        MsgTask msgTask = msgParam.getMsgTask();
        Map<String, String> prop = msgParam.getPropertyParam();   // config_json 解析结果（小程序 appId、secret、debug…）

        // 1. 渲染标题/内容（FreeMarker + _mdp + 模板 script，复用基类）
        MsgResult msgResult = replaceVariable(msgTask, msgParam.getMsgTemplate(), msgProperties);

        // 2. 自己实现：换 access_token → POST subscribeMessage.send
        //    接收人约定写进 msgTaskRecipient.recipient（如 openid）
        for (MsgTaskRecipient r : msgParam.getRecipientList()) {
            sendToWechat(prop, r.getRecipient(), msgResult);
        }

        msgResult.setResult(true);
        return msgResult;
    }

    @Override
    public boolean isSuccess(MsgResult result) {
        return (boolean) result.getResult();
    }
}
```

约定俗成的三个习惯：`recipient` 字段存本渠道的接收标识（用户ID/手机号/邮箱/openid）；支持 `debug=true` 跳过真实发送；`exec` 用 `REQUIRES_NEW` 独立事务（模板渲染和外部调用不回滚任务状态）。

**② 控制台建接口配置**：消息管理 → 接口配置 → 新增：key（如 `wechat-mini`）、接口类型（此例可选「短信」类目借位或按需扩展 msg_type）、执行方式=实现类、实现类下拉选择 `wechatMiniMsgStrategyImpl`、config_json 里配 appId/secret/debug 等参数。

**③ 建模板**：消息模板新增，key 如 `MDM_APPROVAL_WECHAT`，绑定②的接口，content 写 FreeMarker 占位符（或直接存微信模板字段的 JSON）。

**④ 发送**：`msgFacade.sendByTemplateKey(new MsgSendSmsDto()...)` 或按您定义的 DTO 类型发送即可，模板 key 换成 `MDM_APPROVAL_WECHAT`。

**不需要修改任何框架代码或注册表**——策略注册为 Spring Bean + 数据库一条接口配置，扩展即完成。

::: tip 关于 msg_type
`msg_type` 决定模板创建时能选哪类接口、消息任务的 type 值与看板归类。当前枚举固定为 站内信/短信/邮件 三类。如果新渠道在业务上属于全新类型（如「移动端推送」），需要扩展 `MsgTypeEnum` 枚举（`MsgTypeEnum`、字典、前端枚举常量 `console.ts`、模板/任务的类型下拉），工作量集中在枚举与字典，发送链路本身不用改。
:::

### 模式 B：Groovy 脚本（适合轻量/临时渠道）

不写 Java：接口配置直接选「执行方式=脚本」，把一个实现 `MsgTaskStrategy` 的 Groovy 类全文存进 `script`：

```groovy
import top.mddata.console.service.message.strategy.dto.MsgResult

class DingTalkWebhookStrategy implements top.mddata.console.service.message.strategy.MsgTaskStrategy {
    top.mddata.console.service.message.strategy.AbstractMsgTaskStrategy base   // 脚本内不能 @Inject，走 Spring 上下文或自行 new

    @Override
    MsgResult exec(top.mddata.console.service.message.strategy.dto.MsgTaskParam p) {
        // 用 p.getPropertyParam() 取 webhook 地址，p.getMsgTemplate()/getMsgTask() 取模板与参数
        // 调用受限：无文件/网络类 API（Socket 被沙箱拦截）——需要 HTTP 的请走模式 A
        new MsgResult(title: p.getMsgTask().getTitle(), content: p.getMsgTask().getParam(), result: true)
    }
}
```

::: warning
沙箱黑名单禁了 `Socket` 等网络 API，**脚本模式做不了 HTTP 外呼**（钉钉/微信 webhook、推送 SDK 都发不出去）。脚本模式的实际定位是参数加工类轻逻辑；真正的外部渠道请用模式 A。
:::

## 6. 扩展渠道速查表

| 需求           | 做法                                                  |
| ------------ | --------------------------------------------------- |
| 换短信服务商（如华为云） | sms4j 已支持的话：新增接口配置（key=对应厂商标识）+ 新建一个薄策略类；不建议为每家写死分支 |
| 新增邮件账号/隔离发件域 | 新增一条邮件接口配置（不同 config_json），模板分别绑定即可                 |
| 微信模板消息/订阅消息  | 模式 A 自写策略，`recipient` 存 openid                      |
| 移动端推送（极光/个推） | 模式 A 自写策略，SDK 依赖加在 console-service；msg_type 视需要扩展   |
| 临时调整消息内容结构   | 模板的 `script` Groovy 加工参数（同样受沙箱限制）                   |
