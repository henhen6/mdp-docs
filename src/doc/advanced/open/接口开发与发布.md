本篇走完一个开放接口的完整生命周期：**写接口 → 自动注册 → 生成文档 → 同步发布 → 配置权限**。以平台已有的 `user.page` 接口为示例。

## 1. 开发一个开放接口

### 1.1 三步走

**第 1 步：定义出入参**（`md-api/api-pojo` 模块，`top.mddata.api.dto/resp/query` 包）

```java
// top.mddata.api.query.UserQuery —— 查询条件
// top.mddata.api.resp.UserResp  —— 返回对象
// 均为普通 POJO（Serializable），字段名即 bizContent JSON 的字段名
```

**第 2 步：声明接口**（`md-api/api-service` 模块，`top.mddata.api` 包）

`@Open` 标注在 **Service 接口的方法**上（`UserOpenService.java:29,39,48,57`）：

```java
public interface UserOpenService extends SuperService<User> {

    @Open(value = "user.page", description = "分页查询用户信息")
    Page<UserResp> page(PageParams<UserQuery> params);
}
```

**第 3 步：实现并暴露**（同模块 `top.mddata.api.impl` 包）

```java
@DubboService          // 暴露为 Dubbo 服务，网关泛化调用的目标
@Service
public class UserOpenServiceImpl extends SuperServiceImpl<UserMapper, User>
        implements UserOpenService {
    @Override
    public Page<UserResp> page(PageParams<UserQuery> params) { ... }
}
```

重启 api-server（单体版为 worker-server），接口自动注册进开放平台，无需任何手工登记。

### 1.2 @Open 属性

定义见 `md-sop-support/sop-service-support/.../annotation/Open.java:17`：

| 属性 | 默认值 | 说明 |
| ---- | ---- | ---- |
| `value` | — | 接口名（如 `user.page`），**即请求公共参数 `method` 的值，发布后不可改** |
| `description` | `""` | 接口中文描述，注册时写入 `mdo_api.description`（javadoc 运行时反射不到，必须显式写在这里） |
| `version` | `"1.0"` | 版本号，升级接口时递增 |
| `permission` | `false` | 是否需要授权。`true` 时应用必须被分到包含该接口的权限分组才能调用 |
| `needToken` | `true` | 是否要求 accessToken（网关先验非空，拦截器再验有效性） |
| `needSign` | `false` | 是否强制 RSA2 验签（`accessToken.get` 这类高安全接口应开） |
| `hasCommonResponse` | `true` | 是否包公共响应壳（`code/msg/subCode/subMsg/data`）；`false` 只返回 data |

## 2. 自动注册链路

接口不需要人工登记，启动即注册：

```mermaid
sequenceDiagram
    participant S as api-server 启动
    participant C as SopAutoConfiguration
    participant R as ApiRegister/ApiRegisterRunner
    participant G as sop-gateway<br/>ApiRegisterServiceImpl
    participant DB as mdo_api + Redis

    S->>C: Bean 初始化（InitializingBean）
    C->>C: 取 spring.application.name<br/>+ 容器内所有 @DubboService Bean
    C->>R: reg()
    R->>R: 收集接口方法上的 @Open<br/>反射参数生成 paramInfo JSON
    R->>G: @DubboReference 远程调用 register()
    G->>DB: 按 apiName+version 存在则更新<br/>不存在则新增（regSource=1）<br/>预热 Redis（{apiName}:{version}→id）
    Note over R: 注册失败每 5 秒定时重试<br/>（ApiRegisterRunner.java:31-48）
```

关键代码位置：

| 环节 | 类 | 说明 |
| ---- | ---- | ---- |
| 触发点 | `SopAutoConfiguration.java:42-51` | `InitializingBean.afterPropertiesSet`，装配条件 `dubbo.enabled`（默认 true） |
| 注册器 | `ApiRegister.java:85-138` | 只处理实现接口的 `@DubboService` 类，从接口方法收集 `@Open`；`buildRegisterDTO`（:140-193）反射生成参数 JSON |
| 重试 | `ApiRegisterRunner.java:31-48` | 失败后每 5 秒重试（网关还没起来时很有用） |
| 网关接收 | `ApiRegisterServiceImpl.java:46-59` | `@DubboService` 暴露；`appName` 全局唯一校验（:61-65）；`saveOrUpdate` 同时预热 Redis |

::: tip 注册不进去怎么排查

1. api-server 日志里有没有 Dubbo 注册中心连接失败的异常（重试日志每 5 秒一条）；
2. 接口是否标在 **Service 接口**的方法上（标在 impl 类上也能收集，但接口必须存在——`ApiRegister` 只处理实现接口的类）；
3. `mdo_api` 表里 `app_name` 是否被别的服务占用（全局唯一）。

:::

## 3. 文档链路：生成 → 推送 → 同步 → 发布

接口注册只写 `mdo_api`，**不产生文档**。文档是一条独立的两段链路：

```mermaid
flowchart LR
    A["api-server 源码<br/>（javadoc + @Open）"] -->|"① smart-doc-maven-plugin<br/>SopDocBuildTemplate"| B["Torna<br/>文档系统"]
    B -->|"② 运营手动触发<br/>/admin/docInfo/syncAllDoc"| C["开放平台<br/>mdo_doc_info + mdo_doc_content"]
    C -->|"③ 发布"| D["开发者中心<br/>接口文档 + 在线调试"]
```

### 3.1 生成并推送到 Torna（二开工程师侧）

- 文档模板：`SopDocBuildTemplate`（`md-sop-support/.../doc/SopDocBuildTemplate.java:49`），smart-doc 的扩展，经 JDK SPI 注册（`META-INF/services/com.ly.doc.template.IDocBuildTemplate`）；只输出带 `@Open` 的方法（`skipMethod` :224-226），方法标识为「接口名#版本」；
- 推送配置：`md-api/api-server/src/main/resources/smart-doc.json`（`framework: "sop"`、`packageFilters: "top.mddata.api.*"`、`openUrl` 指向 Torna、`appToken` 为 Torna 空间的 open token）；
- 执行：在 `api-server` 目录下运行 `mvn smart-doc:torna-rpc`（插件声明在 `md-api/pom.xml:28-40`，`configFile` 为相对路径 `./src/main/resources/smart-doc.json`，因此必须在 api-server 目录执行），文档即推送到 Torna。

::: warning Torna 需要独立部署

Torna 是外部文档系统，不包含在 MDP 部署单元内。地址配置在系统参数 `ConfigKey.Open.TORNA_SERVER_ADDR`（`ConfigKey.java:68`），开放平台的同步、文档查看页都依赖它。`smart-doc.json` 中的 `appToken` 属敏感凭证，生产环境请替换并通过配置管理下发，不要提交真实值到公开仓库。

:::

### 3.2 同步回开放平台（运营侧）

运营在控制台触发同步（`DocInfoController.java:56,64`）：

- `/admin/docInfo/syncAllDoc`：同步所有文档空间；
- `/admin/docInfo/syncDoc`：同步单个空间。

同步逻辑（`DocInfoServiceImpl.syncDocInfo.java:148-219`）：用 `TornaClient` 调 Torna open API `doc.list` 拉文档列表，按 name+url+version 增改 `mdo_doc_info`；再逐个 `doc.details` 拉详情 JSON 存 `mdo_doc_content`（:274-303）。**没有定时任务，纯手动触发**——接口文档更新后记得重新同步。

### 3.3 发布与对外查看

- 发布：`updatePublish`（`DocInfoServiceImpl.java:77-121`）发布/下线单个文档，**级联联动父节点与所属空间的 publish**；
- 查看：开发者中心公开接口 `/anyUser/client/openDoc/**`（`OpenDocController.java:45`）读文档树与详情；`getDocView` 会按「接口名+版本」关联 `mdo_api`，带出 `needToken`/`needSign` 供在线调试页展示（:237-250）；
- 在线调试：`OpenDocController` 的 `buildDebugParam` 按 mdp-sdk 的规则现场组装签名参数，开发者填自己的 appKey/私钥即可在文档页直接调接口。

## 4. 配置接口权限

接口权限回答的是「**哪个应用能调哪个接口**」，与面向平台用户的 [uri 接口权限](../接口权限.md) 是两套体系。

判定逻辑（网关 `AppManagerImpl.hasPermission`，`AppManagerImpl.java:75-92`）：

```mermaid
flowchart TD
    A["请求到达，查 mdo_api.permission"] --> B{"permission = 0？"}
    B -->|"是（@Open 默认 false）"| C["直接放行"]
    B -->|"否"| D["三表 join 查应用可访问的 apiId 列表<br/>AppGroupRel ⋈ ScopeGroup(state=true) ⋈ GroupApiRel"]
    D --> E{"当前 apiId 在列表中？"}
    E -->|是| C
    E -->|否| F["拒绝：无权访问"]
```

配置动作（运营在控制台操作，详见[应用审核与授权](应用审核与授权.md)）：

1. 建权限分组（`mdo_scope_group`）；
2. 分组关联接口（`mdo_group_api_rel`，改完自动清 `AppApiCkBuilder` 缓存）；
3. 把分组授权给应用（`mdo_app_group_rel`，`/admin/app/saveAppGroup`）。

::: tip 二开建议

新接口默认 `permission=false`（公开给所有有凭证的应用）。涉及敏感主数据写操作的接口（如 `user.batchSave`）建议显式 `permission=true`，把授权决定权交给运营。

:::

## 5. 让接口支持异步回调

耗时接口（如批量导入）支持「先受理、后回调」：SDK 请求带 `notifyUrl` 参数，接口实现处理完后调 facade 触发回调任务：

```java
// 示例：OrgOpenServiceImpl.callNotify（OrgOpenServiceImpl.java:88-106）
notifyAndEventPushFacade.apiCallNotify(notifyInfoDto);
// notifyUrl 取自 OpenContext（即调用方请求表单里的 notifyUrl 参数）
```

回调任务的投递、加密、重试与事件推送共用一条管道，详见[事件回调（平台侧）](事件回调.md)；第三方接收端的写法见[接口回调](../../integration/接口回调.md)。

## 6. 二开注意事项

::: warning method 值即对外契约

`@Open` 的 `value`/`version` 一旦发布，改值等于让第三方 SDK 全部报「接口不存在」。接口演进规则：

- 新增**可选**参数：兼容，直接加；
- 修改语义/删参数/改返回结构：升 `version`（如 `2.0`），旧版本保留一段时间；
- SDK 侧同步新增 `XxxApi`（见 [SDK开发](SDK开发.md)），method 值两侧必须完全一致。

:::

::: warning 异常要抛 OpenException 体系

业务校验失败抛 `ArgumentException`（`GlobalExceptionFilter` 会包装成 `OpenException`，`GlobalExceptionFilter.java:19-36`），网关 `ExceptionExecutorImpl` 按 `<OPEN_ERROR>code@@msg@@solution` 格式解析成标准错误响应。直接抛 RuntimeException 会被包装成笼统的系统错误，第三方无法定位。

:::
